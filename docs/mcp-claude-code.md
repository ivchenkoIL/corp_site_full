# MCP-инструменты Claude Code для игр «Монтаж-Сити»

Настройка, которая даёт Claude Code «глаза и руки» внутри игры: открыть её в
браузере, нажать клавиши, снять скриншот, прочитать консоль и замерить кадры.
Работает одинаково в облачных сессиях Claude Code (claude.ai/code) и в
терминале на Mac — конфигурация лежит в репозитории и подхватывается при
клонировании.

## Что подключено

| Сервер | Зачем | Как запускается |
| --- | --- | --- |
| `playwright` | открыть игру по `file://`, клавиши, JS в странице, скриншоты, консоль | `scripts/mcp/playwright.sh` → `npx @playwright/mcp` |
| `chrome-devtools` | трассировка производительности, долгие кадры, сеть, эмуляция CPU, heap | `scripts/mcp/chrome-devtools.sh` → `npx chrome-devtools-mcp` |
| `context7` | свежая документация WebGL2 / GLSL / Web Audio / Canvas | HTTP `https://mcp.context7.com/mcp` |

Файлы:

- `.mcp.json` — список серверов (project scope: Claude Code читает его из корня).
- `.claude/settings.json` — авто-одобрение этих серверов, разрешения на их
  инструменты, хук `SessionStart`, увеличенный таймаут запуска MCP.
- `scripts/mcp/ensure-chrome.sh` — находит браузер под платформу; на Linux без
  Chrome скачивает Chrome for Testing (со `storage.googleapis.com`, этот домен
  разрешён в облачных сессиях по умолчанию).
- `scripts/mcp/cloud-prepare.sh` — подготовка облачной сессии (браузер +
  прогрев npx-кэша). На Mac молча выходит.
- `games/CLAUDE.md` — правила и протокол проверки правок для агента.

Blender MCP сознательно **не** подключён: игра не загружает ни моделей, ни
картинок — вся геометрия и текстуры строятся кодом. Blender понадобится, только
если игра начнёт загружать glTF/PNG, а это меняет её архитектуру.

## Mac и облако — в чём разница

| | Mac (терминал `claude`) | Облачная сессия claude.ai/code |
| --- | --- | --- |
| Браузер | установленный Chrome, **с окном**, настоящий GPU | Chrome for Testing, headless, WebGL через SwiftShader |
| Годится для | всего, включая FPS и плавность | корректности: рендер, ошибки, коллизии, логика |
| FPS в 3D-версии | реальный | ~1–2 кадра/с — не показатель |
| Context7 | работает | нужно добавить домен (см. ниже) |

Переопределения через переменные окружения: `MCP_HEADLESS=1` — без окна на Mac;
`MCP_CHROME_PATH=/путь/к/chrome` — свой браузер.

## Включение

### 1. Файлы в репозитории

Всё перечисленное выше должно лежать в ветке, с которой стартует сессия
(сейчас — `claude/montazh-city-game-a0nu2m`; после merge PR #36 — в `main`).
Скрипты должны быть исполняемыми (`chmod +x scripts/mcp/*.sh`).

### 2. Облачное окружение на claude.ai/code (один раз)

Откройте claude.ai/code → выбор окружения → редактировать **Default**:

- **Setup script** — вставить строку (кэшируется между сессиями, экономит
  1–3 минуты на старте каждой сессии):

  ```bash
  npx -y @puppeteer/browsers install chrome@stable --path ~/.cache/montazh-mcp/chrome
  ```

- **Network access** — если нужен Context7 в облаке: выбрать **Custom** и
  добавить домен `mcp.context7.com` (остальные домены из списка Trusted
  сохранить). Без этого `context7` в облаке просто не подключится, остальное
  работает.

Без setup-скрипта тоже работает: хук `SessionStart` скачает Chrome сам, но
это происходит в каждой новой сессии и первые 1–3 минуты браузерные серверы
недоступны.

### 3. Mac (если Claude Code стоит локально)

Нужны Node.js 18+ и Google Chrome. Больше ничего: `claude` в корне
репозитория подхватит `.mcp.json`. При первом запуске Claude Code спросит,
доверять ли папке — ответить «да», иначе project-серверы останутся в
состоянии «Pending approval».

## Проверка

В новой сессии попросить:

> Открой игру `games/montazh-city-3d/index.html` через playwright, нажми
> «Новая смена», сними скриншот и покажи ошибки консоли.

Ожидаемо: скриншот с районом и Олегом, `0 errors`. Если сервер не поднялся —
`/mcp` покажет причину (в облаке — попросить агента запустить
`bash scripts/mcp/cloud-prepare.sh --force` и посмотреть stderr).

## Известные мелочи, замеченные при первой проверке

- Консоль 3D-версии выдаёт 15 предупреждений `Canvas2D: Multiple readback
  operations using getImageData are faster with the willReadFrequently
  attribute` (строки ~1046 и ~1140). Это генерация текстур на 2D-canvas;
  лечится `getContext('2d', { willReadFrequently: true })` там, где потом
  вызывается `getImageData`. На игру не влияет, на скорость загрузки — немного.
- Playwright MCP с параметром `filename` сохраняет скриншот относительно
  текущей папки; без параметра возвращает картинку в ответ. Для агента проще
  второе.

## Что проверено (2026-09-04)

Оба браузерных сервера запущены через обёртки на Ubuntu 24.04 x86_64 без
GPU (та же база, что у облачных сессий): Playwright MCP поднялся за 1,8 с
(24 инструмента), Chrome DevTools MCP — за 2,1 с (29 инструментов). 3D-игра
открылась по `file://`, WebGL2 доступен (`SwiftShader`), кнопка «Новая смена»
нажата, получен скриншот геймплея с Олегом и велосипедом, `0 errors`.
FPS в программном рендере — 1,4.
