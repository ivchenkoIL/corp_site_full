# Оснастка замера

Инструменты для измерения производительности «Монтаж-Сити 3D». **Игру они не
трогают**: вся телеметрия ставится в страницу до загрузки, а нужная сцена
задаётся штатным файлом сохранения игры в `localStorage`. В `index.html` нет и
не должно появиться ни одного отладочного крючка ради этих скриптов.

Результаты и разбор — в `docs/RENDER-STATE.md`.

## Что где

| Файл | Назначение |
| --- | --- |
| `perf-inject.js` | Телеметрия. Счётчики draw call'ов и треугольников по проходам, память под текстуры и буферы, время кадра, границы фаз загрузки, таймер-запросы GPU. Ставится через `page.addInitScript`. |
| `perf-probe.mjs` | Прогон трёх контрольных сцен, метрики, разбор кадра по проходам, скриншоты. |
| `perf-trace.mjs` | Сэмплирующий профилировщик V8 через CDP: что делает главный поток внутри кадра. |
| `ext-probe.js` | Снимок возможностей WebGL2. Вставляется в консоль браузера — им снимается Safari. |
| `toc.mjs` | Пересобирает оглавление в начале `index.html`. |

## Требования

Node 18+ и `playwright` (браузеры уже скачаны либо ставятся `npx playwright install chromium`).
Если playwright лежит глобально, а не рядом:

```bash
export NODE_PATH=$(npm root -g)
```

## Команды

```bash
cd games/montazh-city-3d

# полный базовый замер: три сцены, метрики, проходы, скриншоты
node tools/perf-probe.mjs --scene=all --warmup=12 --measure=40 --profile=15 \
     --minFrames=60 --width=1440 --height=900 --dpr=2 \
     --shots=docs/shots/00-base --out=docs/perf/base-chromium-1440x900-dpr2.json

# одна сцена: street | dense | traffic
node tools/perf-probe.mjs --scene=dense --headed

# движок Safari (нужен установленный webkit для playwright)
node tools/perf-probe.mjs --browser=webkit --out=docs/perf/mac-webkit.json

# профиль главного потока
node tools/perf-trace.mjs --scene=traffic --seconds=20

# оглавление
node tools/toc.mjs            # пересобрать
node tools/toc.mjs --check    # проверить, не устарело ли (код возврата 1)
```

### Ключи `perf-probe.mjs`

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `--browser` | `chromium` | `chromium` или `webkit` |
| `--scene` | `all` | `all`, `street`, `dense`, `traffic` |
| `--width` `--height` | 1440×900 | Размер окна в CSS-пикселях |
| `--dpr` | 2 | Плотность пикселей. Игра сама режет её до 1.25 в `resizeGL` |
| `--warmup` | 6 | Секунд на прогрев: прокликать брифинг, дать миру устояться |
| `--measure` | 12 | Минимум секунд в окне замера |
| `--minFrames` | 60 | Минимум чистых кадров. Окно не закроется, пока их не наберётся (потолок — четырёхкратное `--measure`) |
| `--profile` | 6 | Секунд на разбор кадра по проходам |
| `--shots` | — | Куда класть скриншоты (путь от корня репозитория) |
| `--out` | `tools/perf-<browser>.json` | Куда класть JSON |
| `--headed` | выкл. | Показать окно браузера |

## Три вещи, о которых стоит знать

**Посев случайных чисел.** `perf-inject.js` подменяет `Math.random`
детерминированным потоком. Без этого прохожие, собаки и хулиганы каждый раз
расставляются по-новому и сцены не сравнить.

**Кадры с диалогом выбрасываются.** Пока открыт диалог, `step()` не вызывает
`updateWorld`: машины стоят, мир не живёт. Такие кадры не идут в статистику, а
время кадра считается только между соседями по исходной последовательности —
иначе выброшенный кусок склеился бы в один «кадр» на всю паузу.

Реплика прокликивается по одной за кадр, поэтому длинный брифинг на медленной
машине идёт десятки секунд. Отсюда `--minFrames`: окно закрывается по числу
набранных кадров, а не по секундомеру.

**Заявка во время замера протухает.** Игрок стоит на месте, срок заявки
выходит, и HUD показывает «Смена окончена» — это надпись при `S.mission === null`,
а не конец игры. На замер не влияет: район, движение и жители работают как
обычно.
