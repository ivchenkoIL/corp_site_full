# Оснастка замера

Инструменты для измерения производительности «Монтаж-Сити 3D». **Игру они не
трогают**: вся телеметрия ставится в страницу до загрузки, а нужная сцена
задаётся штатным файлом сохранения игры в `localStorage`. В `index.html` нет и
не должно появиться ни одного отладочного крючка ради этих скриптов.

Результаты и разбор — в `docs/RENDER-STATE.md`.

## Что где

| Файл | Назначение |
| --- | --- |
| `mac-baseline.sh` | **Снять всё одной командой.** Ставит недостающее, гоняет три сцены в Chromium и WebKit, снимает профиль, складывает сравнительную таблицу |
| `perf-inject.js` | Телеметрия. Счётчики draw call'ов и треугольников по проходам, память под текстуры и буферы, время кадра, границы фаз загрузки, таймер-запросы GPU. Ставится через `page.addInitScript` |
| `perf-probe.mjs` | Прогон трёх контрольных сцен, метрики, разбор кадра по проходам, скриншоты |
| `perf-trace.mjs` | Сэмплирующий профилировщик V8 через CDP: что делает главный поток внутри кадра |
| `compare.mjs` | Сводит два прогона в одну markdown-таблицу: кадр, вызовы, проходы, расширения, память |
| `ext-probe.js` | Снимок возможностей WebGL2. Вставляется в консоль браузера — им снимается настоящий Safari |
| `scenes.mjs` | Три контрольные сцены, файл сохранения и настройки под них — общий модуль для probe, trace и shot |
| `shot.mjs` | Быстрый снимок сцены и проверка, что игра жива: ошибки страницы, `gl.getError`, фазы загрузки по заданиям, память под текстуры, размер буфера. Точку и час можно задать своими |
| `shot-stats.mjs` | Яркость и контраст скриншотов по полосам (небо / середина / низ), монтаж «до | после». Без зависимостей |
| `find-playwright.mjs` | Ищет playwright по всем обычным местам, чтобы не пришлось выставлять `NODE_PATH` |
| `toc.mjs` | Пересобирает оглавление в начале `index.html` |

## Быстрый старт

Всё делает один скрипт — из папки игры, не из домашней:

```bash
cd <клон репозитория>/games/montazh-city-3d
bash tools/mac-baseline.sh
```

Он сам поставит `playwright` и браузеры, если их нет, и разложит результат по
`docs/perf/` и `docs/shots/00-base-mac/`. Занимает минут десять.

Проверить, что всё на месте, ничего не гоняя и не скачивая:

```bash
bash tools/mac-baseline.sh --dry
```

Скрипт не зависит от текущей папки — можно звать по полному пути откуда
угодно.

## Требования

Node 18+ и `playwright`. Где он лежит — неважно: скрипты ищут его рядом с
собой, выше по дереву, в глобальной папке npm, в домашней и в `NODE_PATH`.
Если не найдут — напечатают, что именно выполнить.

Браузеры: `npx playwright install chromium webkit`.

## Команды по отдельности

```bash
cd <клон репозитория>/games/montazh-city-3d

# полный базовый замер: три сцены, метрики, проходы, скриншоты
node tools/perf-probe.mjs --scene=all --warmup=12 --measure=40 --profile=15 \
     --minFrames=60 --width=1440 --height=900 --dpr=2 \
     --shots=docs/shots/00-base --out=docs/perf/base-chromium-1440x900-dpr2.json

# одна сцена: street | dense | traffic
node tools/perf-probe.mjs --scene=dense --headed

# движок Safari (нужен установленный webkit для playwright)
node tools/perf-probe.mjs --browser=webkit --out=docs/perf/mac-webkit.json

# профиль качества и авто-масштаб (с этапа 02). По умолчанию medium и без
# авто-масштаба: иначе игра сама держит кадр в бюджете, и сравнивать нечего
node tools/perf-probe.mjs --quality=high --out=docs/perf/01-textures-high-chromium.json
node tools/perf-probe.mjs --quality=high --dynamic=1     # посмотреть, как ведёт себя авто-масштаб

# снимок одной сцены за пятнадцать секунд, с проверкой ошибок и памяти
node tools/shot.mjs --scene=dense --quality=high --out=/tmp/dense.png
node tools/shot.mjs --scene=dense --x=50 --z=37 --yaw=3.1416 --hour=12   # крупный план стены в полдень

# яркость и контраст двух кадров, монтаж рядом
node tools/shot-stats.mjs docs/shots/00-base-mac/02-dense-chromium.png docs/shots/01-textures/02-dense-chromium.png --out=/tmp/cmp.png

# профиль главного потока
node tools/perf-trace.mjs --scene=traffic --seconds=20

# сводная таблица по двум прогонам
node tools/compare.mjs docs/perf/mac-chromium.json docs/perf/mac-webkit.json \
     --out=docs/perf/mac-compare.md

# оглавление
node tools/toc.mjs            # пересобрать
node tools/toc.mjs --check    # проверить, не устарело ли (код возврата 1)
```

### Ключи `perf-probe.mjs`

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `--browser` | `chromium` | `chromium` или `webkit` |
| `--scene` | `all` | `all`, `street`, `dense`, `traffic` |
| `--width` `--height` | 1440×900 | Размер окна в CSS-пикселях |
| `--dpr` | 2 | Плотность пикселей. Игра сама режет её до 1.25 в `resizeGL` |
| `--warmup` | 6 | Секунд на прогрев: прокликать брифинг, дать миру устояться |
| `--measure` | 12 | Минимум секунд в окне замера |
| `--minFrames` | 60 | Минимум чистых кадров. Окно не закроется, пока их не наберётся (потолок — четырёхкратное `--measure`) |
| `--profile` | 6 | Секунд на разбор кадра по проходам |
| `--shots` | — | Куда класть скриншоты (путь от корня репозитория) |
| `--out` | `tools/perf-<browser>.json` | Куда класть JSON |
| `--headed` | выкл. | Показать окно браузера |
| `--quality` | `medium` | Профиль качества: `low`, `medium`, `high`. Пишется в настройки игры перед загрузкой |
| `--dynamic` | `0` | Авто-масштаб рендера. Для сравнимых цифр держать выключенным |

## Три вещи, о которых стоит знать

**Таймер-запросы и авто-масштаб.** Пока `perf-inject.js` держит свой запрос
`TIME_ELAPSED_EXT` вокруг кадра, игра свой не открывает (два одновременно
нельзя) и авто-масштаб, если он включён, работает по интервалам кадров, как
в Safari. В обычной игре без оснастки таймер у игры свой.

**Посев случайных чисел.** `perf-inject.js` подменяет `Math.random`
детерминированным потоком. Без этого прохожие, собаки и хулиганы каждый раз
расставляются по-новому и сцены не сравнить.

**Кадры с диалогом выбрасываются.** Пока открыт диалог, `step()` не вызывает
`updateWorld`: машины стоят, мир не живёт. Такие кадры не идут в статистику, а
время кадра считается только между соседями по исходной последовательности —
иначе выброшенный кусок склеился бы в один «кадр» на всю паузу.

Реплика прокликивается по одной за кадр, поэтому длинный брифинг на медленной
машине идёт десятки секунд. Отсюда `--minFrames`: окно закрывается по числу
набранных кадров, а не по секундомеру.

**Заявка во время замера протухает.** Игрок стоит на месте, срок заявки
выходит, и HUD показывает «Смена окончена» — это надпись при `S.mission === null`,
а не конец игры. На замер не влияет: район, движение и жители работают как
обычно.
