# Переезд «Монтаж-Сити» на Babylon.js

Цель: та же игра (смена, заявки, бригада, район), но с настоящими моделями,
фото-текстурами, светом и тенями, как в современных играх. Игра остаётся в
браузере и открывается по ссылке.

## Почему так

- **Babylon.js в браузере, а не Unity, Unreal или Godot.** Игра уже живёт на
  веб-страницах и в артефактах. У Babylon есть всё нужное из коробки: PBR,
  каскадные тени, SSAO, постобработка, glTF со скелетами. Сборка остаётся
  статическими файлами.
- **Логика не переписывается.** Пять тысяч строк правил старой игры (заявки,
  жители, телефон, мини-игры) работают и проверены. Они переехали в модули как
  есть. Меняется только тот, кто рисует кадр.
- **Сначала вертикальный срез.** Сначала один двор сделан в финальном
  качестве, остальной район — в рабочем. Так до переделки всего района видно, как
  будет выглядеть игра и что это стоит по кадру.

## Как это устроено

```
games/montazh-city-3d/index.html    монолит — пока источник правды (его правят другие сессии)
        │  npm run split  (tools/split-legacy.mjs, автоматически, с проверкой)
        ▼
src/legacy/{core,world,game,ui,audio,save}   логика и интерфейс ─┐
src/legacy/render/*                          старый WebGL-рендер  │ оба читают одно состояние S
                                                                  │
src/engine/bridge.js  ◄──────── снимок сущностей ─────────────────┘
        ▼
src/engine/babylon/*   новый рендер: небо, земля, дома, реквизит, люди, машины
src/game/runtime.js    шаги кадра старой игры, кадр рисует Babylon
```

Модули нарезаются из монолита программой, а не руками. Иначе правки, которые
другие сессии продолжают вносить в `index.html`, пришлось бы переносить вручную.
Нарезчик сохраняет порядок исполнения:
- на верхнем уровне модуля остаются только функции и «чистые» данные;
- всё исполняемое уходит в `__init()` модуля, и эти `__init` вызываются в
  исходном порядке разделов;
- запись в чужую переменную переписывается на сеттер.

## Этапы

### Этап 0. Подготовка — сделан

| Что | Где | Статус |
| --- | --- | --- |
| Монолит разрезан на 35 модулей по разделам, всё экспортируется | `src/legacy/`, `tools/split-legacy.mjs` | ✅ |
| Старая игра собирается из модулей в один офлайн-файл | `npm run build:legacy` → `dist-legacy/legacy.html` | ✅ |
| Доказательство, что это та же игра: 4 контрольные сцены, одинаковые время и случайность; состояние мира совпадает точно, кадр — с точностью до шума видеокарты | `npm run check:legacy` | ✅ |
| Логика отделена от графики: мост и снимок сущностей; все места, где логика знает о рендере, перечислены | `src/engine/bridge.js`, `docs/LEGACY-MODULES.md` | ✅ |
| Манифест ассетов: что нужно, требования к моделям, что готово, чем заменено недостающее | `src/assets/manifest.js`, `docs/ASSETS.md` | ✅ |
| Конвейер ассетов: загрузка Poly Haven, упаковка, риггер персонажей, подготовка машин | `tools/fetch-assets.mjs`, `tools/assets/*` | ✅ |

Где логика знает о рендере — всего 9 пар модулей. Это параметры походки
(`GAITS`), габариты машин (`CAR_SPEC`), породы деревьев для столкновений и кнопка
качества в настройках. При полном переезде эти данные уйдут в `world/`.

### Этап 1. Вертикальный срез — сделан

Двор конторы «Монтаж-Сервис» (x 0–20, z 30–65) в финальном качестве. Остальной
район собран той же системой, но с меньшей детализацией.

- **Олег** — своя 3D-модель по образу старой игры, со скелетом. Он ходит, бегает,
  жестикулирует в разговоре, крутит отвёрткой у объекта, садится на велосипед и
  едет: ноги на педалях, руки на руле, наклон в повороте.
- **Бригада** — Ваня, Костя, Саня: свои модели, стоят на разводе и расходятся
  по сценарию старой игры.
- **Жители** — прохожие, бабушки, хулиганы (модели) и собаки (пока кодом).
- **Машины** — «семёрки» семи цветов, колёса крутятся, дальний уровень
  детализации.
- **Велосипед** — собран кодом: рама, колёса со спицами, шатуны, руль,
  багажник.
- **Район** — все дома из данных старой игры:
  - окна как настоящие проёмы с откосами, рамами и стёклами, отражающими небо;
  - цоколи, пояски, парапеты, водостоки;
  - балконы панелек, подъезды с козырьками, гаражи с воротами;
  - вывески со свечением.
- **Земля** — асфальт с разметкой и зебрами, тротуарная плитка, бордюры,
  отмостки. Двор из грязи и травы смешан по шуму, чтобы не было видно повтора.
- **Обстановка** — фонари «кобра» на опорах с изоляторами и провода с провисом.
  На фасаде конторы кондиционеры и камеры. Щиток, лавки, урны, покрышки-клумбы,
  стремянка, стулья-моноблоки, детская площадка, доски объявлений, сорняки.
  Камеры появляются на опорах, когда Олег их ставит.
- **Свет** — фотопанорама неба, солнце с запада-юго-запада, каскадные тени,
  SSAO, свечение, ACES, туман в цвет горизонта. За районом лесополосы и силуэты
  микрорайонов.
- **Вся игра работает**: меню, развод, заявки, телефон, мини-игры, HUD,
  миникарта, сохранения.

Производительность на Mac с Apple M4 в Chromium:
- «высокое», 2160×1350: около 55 кадров в секунду;
- 1280×800: 60 (упирается в вертикальную синхронизацию).

Рендер сам понижает разрешение, если кадр не успевает.

### Этап 2. Весь район — следующий

- Модели, которых нет (список в `docs/ASSETS.md`, раздел 3): собака с четвероногим
  ригом, прохожая, охранник, клиент, фургон, пикап.
- Смена суток. Сейчас свет стоит на 17:00, а часы игры идут. Нужны:
  - небо, которое меняется со временем (панорамы на закат и ночь, их смешение
    или физическая модель неба);
  - фонари и окна, которые зажигаются ночью;
  - фары машин.
- Эффекты старой игры: искры, пыль, дым прибора, лужи и отражения, дождь.
- Клипы действий из Mixamo вместо процедурных: отвёртка, стремянка, замах,
  падение, лай.
- Детализация кварталов по образцу двора конторы: у каждого двора своя
  обстановка.
- Кнопки «качество» и «авто-масштаб» в настройках сделать родными для нового
  рендера, а не через перезагрузку.

### Этап 3. Полировка и выпуск

- Сжатие текстур в KTX2/Basis. Сейчас это WebP на 41 МБ, после сжатия будет
  меньше и быстрее на видеокарте.
- Замер на Safari и слабых машинах, профиль «низкое».
- Хостинг: GitHub Pages или свой сервер. Артефакт Claude вмещает до 64 МБ на
  версию — сейчас сборка влезает.
- Когда новый рендер покроет всё, монолит перестаёт быть источником правды:
  модули `src/legacy/` становятся обычным кодом, а нарезчик отключается.

## Как проверять

```bash
npm run split && npm run build:legacy && npm run check:legacy   # логика не разъехалась с монолитом
npm run dev                                                    # игра на новом движке
node tools/snap.mjs --url http://localhost:5178/index.html --out /tmp/a.png   # снимок, ошибки консоли
```
