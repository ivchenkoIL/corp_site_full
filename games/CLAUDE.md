# games/ — как править игры «Монтаж-Сити» и проверять результат

Две самодостаточные игры без движка и без библиотек, по одному файлу каждая:

- `montazh-city-3d/index.html` — WebGL2, свои GLSL-шейдеры, своя математика 4×4,
  процедурная геометрия (класс `Mesh`), своя скелетная анимация, текстуры
  рисуются на 2D-canvas при загрузке, звук синтезируется Web Audio.
- `montazh-city/index.html` — Canvas 2D.

Нет npm, сборки и сервера: файл открывается по `file://`. Правки — прямо в
`index.html`. Не добавляй внешние зависимости, `<script src>`, `fetch` и файлы
картинок: игра должна оставаться одним офлайн-файлом.

## Инструменты (подключены через `.mcp.json` в корне репозитория)

- **playwright** — открыть игру, нажать клавиши, выполнить JS в странице,
  снять скриншот, прочитать консоль. Основной инструмент проверки.
- **chrome-devtools** — трассировка производительности (долгие кадры, FPS),
  сеть, эмуляция слабого CPU, heap-снимки. Для вопросов «почему тормозит».
- **context7** — актуальная документация по WebGL2 / GLSL ES 3.00 / Web Audio /
  Canvas API. Спрашивай её вместо того, чтобы вспоминать сигнатуры по памяти.

URL игры: `file://<корень репозитория>/games/montazh-city-3d/index.html`
(путь корня даёт `pwd`; в облачной сессии это обычно `/home/user/corp_site_full`).

## Протокол проверки правки (обязателен для физики, анимации, шейдеров)

1. **До правки** — `browser_navigate` на игру, подождать ~4 с, нажать «Новая
   смена» (через `browser_evaluate`: найти `button` с текстом «Новая смена» и
   вызвать `.click()`), снять скриншот, сохранить как эталон «до».
2. Внести изменение в `index.html`.
3. **После правки** — перезагрузить (`browser_navigate` заново), повторить шаги,
   снять скриншот «после», `browser_console_messages` с уровнем `error`:
   ошибок быть не должно. Ошибка компиляции шейдера — это ошибка в консоли.
4. Для физики/движения — воспроизвести ситуацию клавишами через
   `browser_run_code_unsafe` (`page.keyboard.down('KeyW')` → `waitForTimeout`
   → `keyboard.up`) и снять позицию/скорость объекта через `browser_evaluate`
   до и после. Сравнивать числа, а не только картинку.
5. Сообщить пользователю, что изменилось, с двумя скриншотами и числами.

## Что учитывать

- В облачной сессии нет видеокарты: WebGL идёт через SwiftShader, ~1–2 кадра/с.
  Это годится для проверки корректности (рендер, коллизии, ошибки), но **не для
  оценки плавности и FPS**. Замеры производительности делать только на Mac с
  настоящим Chrome (там же обёртки открывают браузер с окном).
- Игра сохраняется в `localStorage`. Обёртки запускают браузер с чистым
  профилем (`--isolated`), поэтому каждый запуск — «новая игра»; для проверки
  прогресса используй меню игры, а не старые сохранения.
- Скриншот без параметра `filename` возвращается прямо в ответ; с `filename`
  сохраняется в `.playwright-mcp/` (папка в `.gitignore`).
- Не коммить `test-*.png`, `.playwright-mcp/` и прочие артефакты проверки.
- Перед серией правок физики — коммит; после — отдельный коммит с понятным
  описанием, чтобы откат был одной командой.
